# Project RE:DEFINE 랜딩페이지 수정 작업 브리프

## 사용 방법

이 문서는 Codex / LazyCodex / opencode가 긴 지시사항을 직접 프롬프트로 받지 못할 때, 먼저 작업 문서로 저장해두고 참조하도록 하기 위한 브리프입니다.

권장 저장 위치:

```bash
docs/redefine-landing-update-brief.md
```

권장 진행 방식:

1. 이 문서를 프로젝트 루트의 `docs/redefine-landing-update-brief.md`로 저장한다.
2. AI 코딩 도구에는 짧은 프롬프트만 입력한다.
3. 한 번에 전체를 수정하지 말고 Phase 1 → Phase 2 → Phase 3 순서로 나눠 작업한다.

---

# 0. 이번 작업의 핵심

이번 랜딩페이지 수정은 아래 세 가지가 핵심입니다.

1. 별탐사 MT 관련 내용은 랜딩페이지에서 노출하지 않는다.
2. 무용극 / Band Session / Writer’s Room 모달 문구를 최신 내용으로 수정한다.
3. 청년동 내부 운영진 소개 섹션을 추가한다.

삭제 예정 프로그램은 아직 최종 확정 전이므로, 이번 작업에서는 새로 추가하거나 강조하지 않는다.

# 2. 별탐사 MT 관련 내용 처리

## 현재 운영 판단

별탐사 MT는 내부 예산 및 운영 방식 조정이 필요한 상태입니다.  
따라서 랜딩페이지에서는 구체적으로 노출하지 않습니다.

## 삭제 또는 비노출 대상 표현

아래 표현이 랜딩페이지에 있다면 삭제하거나 비노출 처리합니다.

- 별탐사 MT
- 포인트로 참여하는 별탐사 MT
- 디스코드 포인트 기반 MT 참여
- 별탐사 MT 일정
- 별탐사 MT 참여 인원

## 대체 문구

꼭 대체 문구가 필요할 때만 아래처럼 일반화합니다.

> 일부 선택형 프로그램은 운영 상황에 따라 확정 후 별도로 안내됩니다.

가능하면 별탐사 MT 관련 영역은 랜딩페이지에서 아예 노출하지 않습니다.

# 3. 무용극 트랙 모달 수정

## 트랙명

무용극

## 제목 / 한 줄 소개

나의 몸짓으로 몰랐던 나를 찾아가는 12주 경험 트랙입니다.

## 소개 문구

누군가의 말이 아닌,  
나의 움직임으로 나를 표현합니다.

움직임 경험이 없어도 괜찮습니다.  
감각을 깨우고, 호흡을 느끼고, 몸의 리듬을 따라가며  
나와 우리의 이야기를 천천히 춤으로 만들어갑니다.

## 이 트랙에서 하는 것

- 몸의 감각을 깨우는 가벼운 움직임
- 공간과 리듬을 활용한 표현 연습
- 나와 우리의 이야기를 춤으로 풀어내는 과정
- Redefine Day를 위한 작품 구성

## 이런 사람에게 추천

- 긴장을 낮추고 내 몸의 감각을 찾고 싶은 사람
- 신체적·정서적 변화의 경험을 원하는 사람
- 함께 만들어가는 과정 속에서 성장하고 싶은 사람

## 진행자 정보 공개 영역

진행자 타이틀:

> 무용극·움직임 기반 표현 워크숍 진행자

진행자 소개 문구:

> 움직임 경험이 없어도 참여할 수 있도록  
> 감각, 호흡, 움직임, 표현을 만들어가는 과정을  
> 단계적으로 안내하는 전문가를 연결할 예정입니다.

## 진행자 이미지 영역

- 진행자 2명 예정
- 사진 2개가 들어갈 수 있는 구조 필요
- 사진 전달 전까지 placeholder 이미지 또는 빈 카드 사용
- 각 카드에는 이름, 역할, 한 줄 소개가 들어갈 수 있게 구성

예시 구조:

```txt
진행자 1
- 사진
- 이름
- 역할
- 한 줄 소개

진행자 2
- 사진
- 이름
- 역할
- 한 줄 소개
```

# 5. Writer’s Room Lab 모달 수정

## 표기 통일

`Writer’s Room`으로 통일합니다.

오타가 있다면 수정합니다.

- 잘못된 표기: `Wirter's Room`
- 올바른 표기: `Writer’s Room`

## Lab명

Writer’s Room

## 소개글

생각보다 우리는 이미 많은 글을 쓰고 있습니다.

오늘의 할 일 리스트,  
배달음식 리뷰,  
유튜브 댓글이나 카톡, 문자까지.

이 모든 것이 나의 글입니다.

거창한 글쓰기는 사양합니다.  
소소하고 다정한 글을 만들어봅니다.

잘 쓰는 방법이나 글쓰기의 규칙을 배우기보다,  
쓰는 근육을 키워보는 시간입니다.

이 과정을 통해 우리는  
자기 자신과 조금 더 친해지게 됩니다.

## 이 Lab에서 하는 것

- 일상 속 다양한 글쓰기를 새롭게 돌아봅니다.  
  예: 일기, 리뷰, 감상문, 에세이, 편지글 등

- 잘 써야 한다는 강박에서 벗어나,  
  “일단 써본다!”는 마음으로 다양한 글쓰기 장르를 가볍게 경험합니다.

- 여러 글쓰기 장르 중 가장 마음에 드는 분야를 골라  
  나만의 원 픽 원고를 완성합니다.

- 제본과 인쇄를 통해  
  나만의 출간본을 소장합니다.

## 이런 사람에게 추천

- 글쓰기를 제대로 배운 다음 정돈된 글을 써야 한다는 부담이 있는 사람
- 글쓰기를 놀이처럼 경험해보고 싶은 사람
- 글을 통해 나의 일상을 새롭게 바라보고 싶은 사람
- 글쓰기는 두렵지만 일단 뭐라도 써보고 싶은 사람
- 누군가에게 글을 평가받는 것이 두려운 사람
- 다른 사람들은 어떻게 생각하고 살아가는지 궁금한 사람
- 글을 통해 타인과 느슨하게 연결되고 싶은 사람

## 운영 안내 문구

서로의 글은 평가하지 않습니다.  
잘 쓰는 글보다, 나에게서 시작한 글을 함께 다룹니다.

## Lab 진행자

옥민아

## 진행자 소개 영역

사진은 추후 전달 예정이므로 placeholder 처리합니다.

구성:

- 사진
- 이름: 옥민아
- 역할: Writer’s Room Lab 진행자
- 한 줄 소개: 추후 확정 또는 임시 문구 사용

임시 문구:

> 일상의 언어를 글로 꺼내고,  
> 나만의 원고로 정리하는 과정을 함께 안내합니다.

# 6. 청년동 내부 운영진 소개 섹션 추가

## 섹션 목적

트랙 운영자 / 강사 소개와 별도로, 청년동 내부 운영진 소개 섹션을 추가합니다.

청년동 운영진은 프로그램 전체 운영, 일정 안내, 공간 운영, 커뮤니티 운영을 담당하는 사람들입니다.  
트랙 운영자와 역할이 다르므로 시각적으로 구분합니다.

## 추천 위치

트랙 / Lab 소개 섹션 하단 또는 신청 안내 섹션 이전

추천:

> 트랙 / Lab 소개 섹션 하단

## 섹션 제목

함께 운영하는 사람들

## 보조 문구

리디파인은 청년동 운영진과 트랙 운영자가 함께  
참여자의 속도에 맞는 경험을 만들어갑니다.

청년동 운영진은 전체 일정, 참여 안내, 공간 운영, 커뮤니티 운영을 함께 담당합니다.

## 카드 구성

기존 트랙 운영자 모달 또는 강사 소개 카드와 유사한 구조를 사용합니다.

각 카드 구성:

- 사진
- 이름
- 역할
- 담당 영역
- 한 줄 소개

## 예시 카드 1

- 사진: 추후 전달
- 이름: 추후 입력
- 역할: 프로젝트 운영
- 담당 영역: 전체 일정 / 참여 안내 / 프로그램 운영
- 한 줄 소개: 참여자가 자신의 속도에 맞게 프로그램을 따라갈 수 있도록 운영 전반을 함께합니다.

## 예시 카드 2

- 사진: 추후 전달
- 이름: 추후 입력
- 역할: 커뮤니티 운영
- 담당 영역: 디스코드 / 클럽 활동 / 참여 안내
- 한 줄 소개: 온라인 커뮤니티와 활동 참여가 부담스럽지 않도록 안내합니다.

## 예시 카드 3

- 사진: 추후 전달
- 이름: 추후 입력
- 역할: 공간 운영
- 담당 영역: 청년동 공간 / 일정 조율 / 현장 운영
- 한 줄 소개: 청년동에서의 활동이 안정적으로 이어질 수 있도록 현장을 지원합니다.

## 주의

- 이름과 사진은 아직 확정 전이므로 placeholder로 구성
- 실제 사진 전달 후 이미지 경로만 교체할 수 있도록 구조화
- 운영진 섹션은 너무 무겁게 보이지 않게 구성
- “상담자”, “치료자”처럼 보이지 않게 표현
- 역할은 운영, 안내, 공간, 커뮤니티 중심으로 정리

# 9. Phase별 작업 권장

## Phase 1: 현재 구조 확인

목표:

- 관련 섹션과 모달 구조만 확인
- 아직 수정하지 않음

확인할 것:

목표:

- placeholder 기반 운영진 카드 섹션 추가
- 모바일 가독성 확인
- 사진 교체가 쉬운 구조로 구성

## Phase 4: QA

확인:

- 모달 열기/닫기 정상
- FAQ 토글 정상
- 신청 버튼 정상
- 모바일 레이아웃 정상
- git diff --check 통과
